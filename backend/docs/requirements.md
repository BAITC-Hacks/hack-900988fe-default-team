Основание: HACKATHON_PLAN.md, API_CONTRACT.md, согласованные расширения theme/teams и исходный кейс AI Sana. Общие файлы обновляет интегратор. Готовность интерфейса проверяется отдельно.

## Проверка

Из backend:

```powershell
npm ci
npm test
npm run test:acceptance
```

Acceptance запускает отдельный процесс API с временной SQLite и отключённым внешним провайдером. Проверяет все четыре уровня seed, публикацию с рейтингом 10, запрет публикации неподтверждённой карточки, каталог, два отклика, ручные статусы, редактирование, рейтинг 100 и сохранение после перезапуска. Рабочая база не используется.

Для уже запущенного сервера `npm run smoke` выполняет только чтение health, Swagger UI и OpenAPI. Полный suite не требует реального ключа. Отдельной сборки JavaScript и конфигурации линтера нет; синтаксис проверяется `node --check`, production-упаковка — сборкой Docker.

## Демо-набор

| ID | Задача / тема | Баллы | Уровень |
|---|---|---:|---|
| task_1 | Очередь в столовой / operations | 30 | draft |
| task_2 | Инструкции адаптации / hr | 50 | working |
| task_3 | Сводка расходов / finance | 80 | ready |
| task_4 | Подбор заданий / education | 90 | priority |
| task_5 | Энергопотребление / sustainability | 100 | priority |

Все пять карточек опубликованы, включая draft как **уровень рейтинга**. Это отличается от статуса непубличной задачи draft. Все отклики изначально pending. Ссылки example.com — синтетические примеры, а не готовые внешние прототипы.

Новый seed применяется только к пустой базе. Существующие карточки не перезаписываются. Для чистого демо укажите отдельный новый файл базы через настройку из backend/.env.example. Рабочую базу удалять не требуется; API сброса данных нет.

## Ограничения и интеграция

- Один процесс backend на файл SQLite: память процесса содержит рабочее представление данных. Несколько реплик с общей базой в MVP не поддерживаются.
- Незавершённые анализы хранятся в памяти; после перезапуска analyze нужно повторить. Созданные задачи, команды и отклики сохраняются.
- Совпадение цитаты с источником не гарантирует её смысловую классификацию: пользователь проверяет поля перед подтверждением. AI не подтверждает сведения автоматически.
- Реальный внешний LLM проверяется отдельно в окружении развёртывания. Без него fallback предусмотрен ТЗ.
- Frontend использует backend enum тем и формулу рейтинга, передаёт полный confirmedFields, сохраняет текущую карточку перед publish, показывает recommendation и профили teams.
- В разделе 2 исходного кейса упомянуты баллы командам за подтверждённые этапы. В разделе 3 обязательных модулей их нет, раздел 7 разрешает демонстрацию без проектного трекера. В текущем контракте нет этапов или формулы баллов команды. Расширение требует согласования; готовность здесь относится к обязательному MVP до ручного решения бизнеса.
- Интегратор обновляет общий контракт/README и исключает ранее отслеженные runtime-артефакты из Git. Backend .gitignore предотвращает добавление новых артефактов, но не убирает существующие из индекса.
