## Журнал

### 2026-09-23 — первый рабочий блок backend MVP

- Реализованы Node.js HTTP-каркас, API по существующему контракту, in-memory модели задач/команд/откликов и пять синтетических seed-записей каждого типа.
- Добавлен scoring 0–100 по семи категориям; начисление только непустому подтверждённому полю; рекомендации по недостающим сведениям.
- Добавлены анализ черновика с OpenAI Responses JSON Schema Structured Output и локальный fallback, compose карточки, CRUD задач, публикация, каталог и ручные статусы откликов.
- Изменены: `backend/package.json`, `backend/src/*`, `backend/test/scoring.test.js`, `backend/README.md`, `backend/.env.example`.
- Проверки: `node --test` — 2/2 прошли; smoke check `GET /api/health` вернул `{"status":"ok"}`, `GET /api/tasks` вернул 5 seed-задач.
- Известное ограничение: хранилище in-memory, поэтому записи теряются при перезапуске; `DATABASE_URL` пока резерв для подключения постоянной БД.
- Следующий шаг: проверить API smoke-сценарием, корректность ответа OpenAI с реальным настроенным ключом и согласовать поле связи с бизнесом.

## Предложения для интеграции

- Scoring требует категорию `businessLink` (10 баллов), но среди описанных контрактом извлечённых полей такого ключа нет. Предложение на интеграцию: определить в общей схеме задачи явное строковое поле `businessLink` (старая структура: отсутствует; предлагаемая: `businessLink: string`), включить его в `extractedFields`/редактор и правила подтверждения. До согласования поле поддерживается backend в `fields`, но AI-схема его не извлекает.
