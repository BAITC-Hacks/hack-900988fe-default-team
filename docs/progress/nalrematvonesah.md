### По аудиту ТЗ — передача владельцу frontend и интегратору

- **Необязательное расширение этапов команды (требует решения).** В текущем API есть только задачи, команды и отклики; баллов за этапы нет. Причина предложения: шаг 8 исходного кейса упоминает подтверждённый прогресс, хотя раздел 7 разрешает MVP без трекера. Если организаторы требуют шаг 8, предлагается отдельно согласовать POST /api/proposals/:proposalId/milestones с {title, evidenceUrl}, POST /api/milestones/:milestoneId/confirm и GET /api/proposals/:proposalId/milestones. Предлагаемый ответ этапа: {id, proposalId, title, evidenceUrl, status: submitted|confirmed, earnedPoints: number}; подтверждение только для selected-отклика, повторное подтверждение идемпотентно. Размер баллов необходимо согласовать; рейтинг задачи не меняется. Эти endpoints и поля не реализованы и не внесены в общий контракт без согласования.

Проверки: ни одного/одно подтверждение — 0; оба — 20; изменение need со снятием подтверждения снимает 20.
- **Темы.** Раньше UI отправлял строки «AI и данные», «Экология», «Сервис», «Логистика», «Образование», а createTask/updateTask отбрасывали theme.
